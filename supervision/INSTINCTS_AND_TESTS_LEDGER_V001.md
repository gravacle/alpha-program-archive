## PROVENANCE-CLEAN REQUIREMENT (the hard gate on any accepted proof — principal, 2026-08-13)
Any proof/result we PICK from this analysis must pass a **full dependency audit**, separate from and stronger than the reversion flag: trace every ingredient of the claim down to surface **bedrock**, tag each node surface-native or imported, and confirm **ZERO imported-machinery-value nodes anywhere in the chain** — no imported GR length, no ℓ_P, no fiber radius R, no metric datum, no adopted/undetermined value that the surface does not itself determine. A *single* imported-value dependency **REJECTS** the proof, however clean the top-level argument looks (the reversion flag catches machinery *reasoning*; this catches a machinery *value buried in the chain* — the S16/S13/F6b failure mode, where a "surface-native" result silently stood on the imported GR scale). **The audit is run by the EXTERNAL lanes, not by the builder or the registrar.** A proof that determines α must be shown to NOT route through the imported GR scale (or any import) at any depth. Result of every audit appends here: claim → dependency chain → `IMPORTED_VALUE_NODES = none | <list>` → accept/reject.

## THE REVIEW PANEL (for a machinery-free result — two axes, three reviewers; principal, 2026-08-13)
A bare-surface result that is *also the hoped-for answer* is exposed to BOTH lineage failure modes and needs both axes covered:
- **Rigor / provenance axis — EXTERNAL, cross-lineage (Codex + Dario):** over-claims, imported values, the full provenance audit. Failure mode: reverts to machinery → fenced with the CHECKER MACHINERY-REVERSION FENCE (machinery-as-suspect allowed, machinery-as-authority forbidden; a refutation must stand on bedrock).
- **Bedrock-fidelity axis — SAME-lineage adversary (a fresh Fable, briefed to break it):** attacks the residual and the over-closure on bedrock. Failure mode: over-closure/confirms → briefed adversarially, and *a bedrock hole from the sympathetic lineage is near-decisive*.
- **DECISION RULE:** accept only if (a) no reviewer finds a BEDROCK hole (machinery-only objections do not refute), (b) provenance is clean (zero imported-value nodes, no unverifiable premise node), and (c) no reviewer reverted to machinery. Any bedrock hole from any of the three refutes.

## DEFEAT-PROVENANCE REQUIREMENT (the bare surface arbitrates in BOTH directions — principal, 2026-08-13)
Symmetric to the confirmation gate: a **refutation** (a claimed bedrock hole) counts ONLY if the hole is itself provenance-clean — a genuine surface-native defect that does **not** rest on any imported machinery concept, value, or premise the bare surface may not recognize. Just as machinery may not DEFEND the result (machinery-as-authority forbidden for defense), it may not DEFEAT it (forbidden for attack). Every claimed hole is routed to a **defeat-provenance audit**, cross-checked by the OTHER reviewers (not the registrar): does the defeat depend on something the surface does not carry? A machinery-dependent "hole" is a **FALSE defeat** — logged, but it does not sink the result. Both the confirmation axis AND the refutation axis owe provenance. A result stands unless it is defeated on bedrock the surface actually recognizes; it is accepted only if confirmed on that same bedrock.

## CONFIRMATION AXIS (attack in the sense of confirm — principal, 2026-08-13)
Refutation reviewers can only report "we could not break it" (negative evidence). A complete panel adds an independent **COLD RE-DERIVATION** — a cross-lineage party given only the bedrock and the *question*, never the subject's answer — that derives its own verdict. Independently reaching the same result (ideally the same surface-native invariant) is **positive overdetermination**, far stronger than absence-of-hole; a cold **divergence** is a red flag even if no hole was found. Accept requires: refutation axis finds no *surface-native* hole (defeat-provenance clean) AND the confirmation axis independently lands on the same result.

## PROOF-OBJECT REQUIREMENT (attach the adversarial — principal, 2026-08-13)
At a proof juncture a result is a "proof" ONLY as an **attached dossier**, never as the bare claim: the result artifact + EVERY adversarial review (all axes — external rigor + external provenance + same-lineage bedrock-fidelity), each **sealed by digest with its .seal.sha256 sidecar**, each showing what it attacked and its per-gate verdict. The adversarial reviews are first-class attached evidence, so any later audit can read the attacks and outcomes directly, not trust the registrar's summary. Reviews run as my own agents (e.g. the Fable adversary) get the SAME custody as fired-relay checks — seal, sidecar, attachment — no exceptions. The dossier is what gets registered/pushed; a claim without its attached surviving-attack record is not a proof.

## HOW TO USE (the protocol)
1. A bare-surface test names the instinct(s) it tests, **strips the machinery** (names the forbidden imports), works on bedrock, and returns `MACHINERY_INVOKED`.
2. The external checker verifies (i) the finding and (ii) **whether the test reverted to machinery** (`REVERTED_TO_MACHINERY = no | yes`).
3. Append the result here: instinct → test artifact (digest) → result → reversion-status.
4. An instinct is **CONFIRMED** only by a test that stayed on bedrock (reversion = no, checked) AND an external lane verified. A machinery-reverted result is **INCONCLUSIVE (reverted)** — it does not move the instinct.
5. The instinct can also **overturn bedrock or machinery**: if a clean bare-surface test contradicts a booked (machinery) finding, the booked finding is flagged as artifact; if it contradicts stated bedrock, bedrock is re-examined.
