## Lead determination — CLAIMED

**PARTIAL.** The derived Gate-4 incidence connection is the correct
**per-object connection carrier** for RA27-3, but it is not the whole RA27-3
**refinement-transport field**.

The two phrases use `transport` at different indices:

```text
Gate 4: edge/path transport inside one finite record complex K;
RA27-3: transport of the connection field along an arrow K -> K' in Ref_a.
```

The different-word/same-object probe lands positively at the first level:
`U_e`, the edge 1-cochain `a`, and “unit-weight covariant incidence modulo
gauge” are three displays of the same finite record-side connection type. The
same-word/different-object probe blocks full identification at the second
level: edge/path composition does not assign connection values to the new
interior edges created by a subdivision.

The resulting work reduction is real. B1a no longer needs to derive **a
connection at all**. It needs to derive a **connection-refinement lift** for
that already-derived object, natural over the working `Ref_a` class and
compatible with incidence, the cell coframe, and `Vol_4`. Current sealed stock
does not force the lift: the interior-edge assignment remains a free datum.

Nothing here identifies the discrete connection with electromagnetism, a
smooth public field, a Maxwell connection, or a response object.

## 2. AS2 — supply-side object and S08 — CLAIMED

### 2.1 Displayed type and domain

S1/S2 display an object of `BareRec_2` as

```text
(K,r,L,U),
```

where:

- `K` is a finite oriented regular CW complex through dimension two;
- every vertex `v` carries a one-dimensional Hermitian fibre `L_v`;
- every oriented edge `e:s->t` carries unitary transport
  `U_e:L_s->L_t`, with `U_(bar e)=U_e^(-1)`;
- no face-flatness is imposed, so nontrivial loop/face holonomy remains
  admissible;
- vertex rephasing acts as
  `U_e -> h_t U_e h_s^(-1)`;
- the same fixed-complex data admit the cochain display
  `(d_0 lambda)_e=lambda_t-lambda_s`,
  `(d_1 a)_f=sum incidence(f,e)a_e`, and `d_1 d_0=0`.

Thus the supplied object is a finite record-incidence connection, not a
smooth one-form. It transports one-dimensional vertex-fibre data along
oriented edges of one complex.

### 2.2 Derivation basis

S1 states the Gate-4 premises and derived conclusion:

```text
local vertex/edge incidence carriers;
per-vertex U(1) rephasing redundancy;
edge/path composition with no interior residue;
naturality over universal-edge isomorphisms;
one-record normalization;

=> unit-weight covariant incidence modulo gauge,
   with loop holonomy as the physical residual.

status = DERIVED_WITHIN_GATE4_ENUMERATED_FAMILY.
```

This is not merely a similarly named structure. It is exactly a connection on
the same finite record-complex carrier RA27 uses.

### 2.3 What its own morphisms do—and do not do

S2 also defines a connection-preserving `BareRec_2` morphism `(i,eta)` by

```text
i: injective cellular map preserving degree, incidence, orientation,
   face attaching maps, and roots;
eta_t U_e = U_(i(e)) eta_s on each domain edge.
```

This proves an existing compatibility interface for edges that have images.
It does not populate a subdivision target's **new interior edges**. Nor does it
show that every `Ref_a` arrow is such a morphism: `A1` and `A2` replace cells by
families of subcells and introduce edges with no domain antecedent. The
morphism equation is a receiver for inherited edges, not a generator for new
ones.

### 2.4 Exact S08 scope

> public field, a Maxwell connection, or a response object.”

It further says downstream response, CTP, Maxwell stiffness, and alpha-path

Using the derived object as the **internal record-side connection carrier** in
RA27 is outside that bar. This report makes no prohibited identification: it

### 3.1 The two name traps

**Different words, same object.** `U_e`, edge cochain `a`, and “unit-weight
covariant incidence modulo gauge” coincide in type and transformation law.
Treating the incidence connection as unrelated to RA27's per-object connection

inside `K`. RA27 “transport” is a natural lift across `K -> K'` in `Ref_a`.
Treating the first as the second would repeat the unproved-transport failure
the program has already recorded for values.
