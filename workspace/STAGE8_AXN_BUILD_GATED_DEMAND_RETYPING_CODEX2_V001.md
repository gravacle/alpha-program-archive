## 2. Retyping rule

The earlier label `UNIVERSAL-GATED` did not decide what kind of object could
discharge the gate. This report uses three non-overlapping types:

| type | exact meaning |
|---|---|
| `INSTANCE-DEMANDING` | the demand requires a particular carrier, carrier package, family, or domain object to be supplied; a theorem quantified over possible objects does not produce that object |
| `UNIFORMITY-SATISFIABLE` | the demand requires a receiver-bound conclusion for every object already admitted or produced under sealed predicates; no particular carrier form or member need be selected |
| `MIXED` | the same consumer requires both an actual supplied carrier/family/domain object and a theorem uniform over all admitted members |

An ordinary runtime input does not by itself make a law
`INSTANCE-DEMANDING`. The question is whether resolving the *carrier-class
gate* requires selecting a particular carrier/class, or whether a theorem
over every independently supplied admissible output is enough. Vacuous
universalization is barred: each application still requires a real typed U1
output at its receiver.

The key distinction is also type-theoretic. The **class of all packages that
satisfy an existing predicate** is a quantifier domain. It is not itself the
primitive-density carrier `A_c`. Quantifying over that class selects neither
a carrier form nor a member. Substituting that meta-class for `A_c` would be a
type error and is not done below.
